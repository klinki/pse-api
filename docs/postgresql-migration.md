# Migrating from MySQL to PostgreSQL

From this version on the API uses PostgreSQL (Npgsql EF Core provider) instead of MySQL (Pomelo).
The application does not migrate its database on startup, and existing data has to be copied over
once. This document describes that one-off switch.

## What changes

| | MySQL (before) | PostgreSQL (after) |
|---|---|---|
| EF Core provider | Pomelo.EntityFrameworkCore.MySql 9 (EF Core 9) | Npgsql.EntityFrameworkCore.PostgreSQL 11 (EF Core 11) |
| Health check (`/healthz`) | `AddMySql` | `AddNpgSql` |
| Connection string | `Server=db;port=3306;user=pse;password=…;Database=pse;GuidFormat=None` | `Host=db;Port=5432;Database=pse;Username=pse;Password=…` |
| Ids | `AUTO_INCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` |
| BIC / ISIN comparison | case-insensitive (`utf8mb3_general_ci`) | case-insensitive ICU collation `case_insensitive` (needs PostgreSQL with ICU, which the official images have) |
| `trades (ISIN, Date)` unique key | added manually, not in the EF model | part of the EF model (`IX_trades_ISIN_Date`) |

Table and column names are unchanged (`days`, `Stocks`, `trades`, PascalCase columns).

The old MySQL migrations were removed; the schema is created by the single `InitialPostgreSql` migration.

## Files

- `scripts/postgres/schema.sql` – idempotent SQL script of all EF migrations. Regenerate after adding a migration:
  ```sh
  dotnet tool restore
  ConnectionStrings__Default="Host=localhost;Database=pse" \
    dotnet ef migrations script --idempotent --project PseApi -o scripts/postgres/schema.sql
  ```
- `scripts/postgres/migrate-from-mysql.sh` – copies `days`, `Stocks` and `trades`, resets the identity
  sequences and compares row counts and checksums (ids, volumes, prices, text lengths) of both databases.
  It refuses to write into non-empty tables unless `TRUNCATE=1` is set, and exits non-zero on any mismatch.

## Runbook

Placeholders: `<mysql-container>`, `<postgres-container>`, `<pse-app>` (compose service of the API).

1. **Create the database and user** (as a PostgreSQL superuser):
   ```sql
   CREATE ROLE pse LOGIN PASSWORD '<new password>';
   CREATE DATABASE pse OWNER pse ENCODING 'UTF8' TEMPLATE template0;
   ```

2. **Create the schema** (as `pse`, so it owns the tables):
   ```sh
   docker exec -i -e PGPASSWORD='<pse password>' <postgres-container> \
     psql -X -v ON_ERROR_STOP=1 -U pse -d pse < scripts/postgres/schema.sql
   ```

3. **Stop the API** so nothing writes to MySQL during the copy (the API stores trades on demand and in
   the nightly job at 23:50 Mon–Fri):
   ```sh
   docker compose stop <pse-app>
   ```

4. **Back up MySQL**:
   ```sh
   docker exec -e MYSQL_PWD='<mysql pse password>' <mysql-container> \
     mysqldump -upse --single-transaction --default-character-set=utf8mb4 pse > pse-mysql-$(date -u +%Y%m%dT%H%M%SZ).sql
   ```

5. **Copy the data** (about 1M trade rows; expected to take a minute or two):
   ```sh
   export MYSQL_PWD='<mysql pse password>' PGPASSWORD='<pse password>'
   MYSQL_CLIENT="docker exec -i -e MYSQL_PWD <mysql-container> mysql -upse" \
   PSQL_CLIENT="docker exec -i -e PGPASSWORD <postgres-container> psql -U pse -d pse" \
     scripts/postgres/migrate-from-mysql.sh
   ```
   The script prints both sets of checksums and ends with `Done - data in PostgreSQL matches MySQL`.
   After a failed attempt, re-run it with `TRUNCATE=1`.

6. **Switch the API** – deploy the new image and change its environment:
   - `ConnectionStrings__Default: Host=<postgres host>;Port=5432;Database=pse;Username=pse;Password=…`
   - put the API container on a network where it can reach the PostgreSQL container
   ```sh
   docker compose up -d <pse-app>
   ```

7. **Verify**: `/healthz` returns `Healthy`, and `/api/days`, `/api/stocks`, `/api/trades/<bic>` and
   `/api/trades/isin/<isin>` return data (lower-case identifiers must work too).

## Rollback

MySQL is not modified by any of the steps above. To roll back, redeploy the previous (MySQL) image with the
previous connection string. Trades downloaded while running on PostgreSQL will be downloaded again by the
MySQL version on demand.

Keep the MySQL database until the PostgreSQL version has run through at least one nightly import.
